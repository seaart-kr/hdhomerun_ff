# HDHomeRun Live for Shyni

FF(FlaskFarm)에서 HDHomeRun 채널을 직접 읽고, Shyni 라이브 TV에 넣을 M3U/HLS 주소를 제공하는 플러그인입니다.

## 0.6.5 · 채널별·그룹별 출력 지정

**채널별 지정 → 그룹별 지정 → 기본 출력** 순서로 원본 패스 또는 변환 방식을 선택할 수 있습니다. **재생 / API → 그룹별 출력 방식**에서 그룹 출력을 저장하고, **장비 / 채널 → 출력 방식**에서 필요한 채널만 예외로 지정하세요. 그룹은 자동 분류와 수동 그룹 지정을 모두 따릅니다. `따름`을 선택해 저장하면 해당 예외를 해제합니다. 재스캔·기준표 갱신·FF 재시작 후에도 지정이 유지됩니다.

장비 / 채널 목록은 전체 채널 번호순 대신 그룹별로 묶어 표시합니다. 각 그룹 제목에 채널 수를 표시하고 그룹 안에서는 기존 채널 순서를 유지합니다. 수동 그룹을 바꾸면 변경한 그룹 위치로 다시 표시합니다.

공용 서버의 그룹 기준표와 별도의 커스텀·방송사 아이콘 목록을 함께 받아오도록 아이콘 연동을 수정했습니다. 이전 갱신에서 그룹만 저장됐다면 **기본 그룹 / 아이콘 불러오기·갱신**을 다시 실행하고 Shyni 채널 목록도 새로고침하세요. Shyni는 M3U의 `tvg-logo`로 아이콘을 읽으므로 아이콘 때문에 EPG 주소를 추가할 필요는 없습니다.

아이콘은 정식 이름·별칭 후보를 함께 비교해 커스텀 및 공급자 우선순위를 적용합니다. 한글 별칭으로 잡힌 우선 아이콘보다 다른 공급자의 정식 이름 아이콘이 먼저 선택되던 경우(MBN 플러스 등)를 수정했습니다. 수정 적용 후 기준표를 갱신하면 새 우선순위가 저장되며 수동 아이콘 지정은 계속 최우선입니다.

예를 들어 기본 출력을 `원본 유지`로 저장하고, `지상파` 그룹은 `VAAPI 변환`, `스포츠` 그룹은 `원본 유지`로 저장하면 지상파만 변환하고 다른 방송은 원본으로 봅니다. 특정 스포츠 채널을 CPU 변환으로 지정하면 그 채널은 채널별 설정이 우선합니다. VAAPI·NVIDIA 지정은 해당 서버의 실제 변환 검사를 통과해야 저장할 수 있습니다. 화질·비트레이트 옵션은 변환 채널에 공통으로 사용합니다.

**혼합 출력에는 반드시 Shyni 기본 M3U(`/hdhomerun_ff/api/m3u_shyni`)를 사용하세요.** 기존 VAAPI·CPU·NVIDIA·원본 전용 M3U는 모든 채널을 해당 방식으로 고정하므로 개별 지정을 반영하지 않습니다. 출력 지정을 바꾼 뒤에는 Shyni에서 M3U 채널 목록을 새로고침하고 다시 재생하세요. 재생 중인 채널의 출력은 목록을 갱신하기 전까지 유지됩니다. 새로 업데이트한 설치본은 기존 기본 출력을 그대로 유지하며 그룹/채널 지정을 자동으로 추가하지 않습니다.

`원본 유지(copy)`는 영상·음성을 재인코딩하지 않고 HLS로 제공합니다. 영상은 원본으로 유지하고 음성만 AAC로 바꾸려면 `영상 원본 · 음성 AAC`를 선택할 수 있습니다.

## 0.6.4 · 채널 아이콘·수동 그룹과 약 10초 재생 준비

공용 그룹 기준표를 갱신할 때 채널 아이콘도 함께 저장합니다. 공용 커스텀 아이콘을 우선하고 방송사 기본 아이콘을 다음으로 사용하며, 기존 TVH M3U GitHub의 이미지 주소를 재사용합니다. M3U의 `tvg-logo`에 반영하므로 다른 플러그인 설치가 필요하지 않습니다. 기존 기준표를 받은 사용자는 **장비 / 채널 → 기본 그룹 / 아이콘 불러오기 · 갱신**을 한 번 실행하세요.

채널별 **그룹 저장**에서 기존 그룹을 선택하거나 새 이름을 입력할 수 있습니다. 수동 그룹은 자동 분류보다 우선하며 재스캔·기준표 갱신 후에도 유지됩니다. 비워서 저장하면 자동 분류로 돌아갑니다. 아이콘도 URL을 직접 입력해 **아이콘 저장**하면 공용 아이콘보다 우선하며, 비워서 저장하면 자동 아이콘으로 돌아갑니다. 공용 아이콘·그룹은 로컬 기준표에 캐시하고 메뉴 조회·재생 시 별도 서버 요청을 하지 않습니다. 이미지는 플레이어·브라우저에서 해당 이미지 주소를 읽습니다.

기본 첫 재생 준비 분량은 약 10초(지연 4초 + 제공 영상 6초)입니다. 이전 기본 지연 12초를 쓰는 설치본은 업데이트 후 플러그인을 다시 불러올 때 4초로 한 번 전환하며, 다른 사용자 설정값은 보존합니다. 이후에는 지연 값을 직접 바꿀 수 있습니다. 원본 연결·수신 속도·플레이어 자체 버퍼에 따라 실제 화면이 나오는 시점은 더 늦을 수 있습니다.

그룹·아이콘 변경 후에는 **Shyni에서 M3U 채널 목록을 다시 가져와야 합니다.** FF 재시작만으로 Shyni가 보관한 채널 정보까지 갱신되지는 않습니다.

## 0.6.3 · 공용 기준표로 기본 채널 그룹 분류

홈런 플러그인 단독으로 TVH M3U와 같은 공용 채널 기준표를 사용합니다. **장비 / 채널 → 기본 그룹 / 아이콘 불러오기 · 갱신**을 한 번 실행하면 기존 채널과 이후 가져오거나 스캔한 채널이 정식 이름·별칭에 따라 분류됩니다. TVH M3U 플러그인이나 TVHeadend를 설치할 필요는 없습니다.

지상파, 종합편성, 연예/오락, 드라마, 영화, 스포츠, 뉴스/경제, 음악, 어린이/만화 등의 그룹과 순서를 재사용합니다. 채널 목록에 그룹을 표시하고 M3U의 `group-title`과 그룹 순서에 반영합니다. 일치하지 않는 이름은 `그룹 없음`으로 두며 부분 문자열로 임의 추측하지 않습니다. 기존에 별도로 지정한 그룹과 채널 사용 선택은 유지합니다.

기준표는 사용자가 갱신 버튼을 누를 때만 공용 서버에서 읽어 이 플러그인의 로컬 DB에 저장합니다. 재생·메뉴 조회 중에는 서버에 접속하지 않으며, 연결 실패나 빈 응답은 저장된 기준표를 교체하지 않습니다. 공용 서버의 분류가 바뀌면 같은 버튼으로 갱신할 수 있습니다. 공개된 읽기 전용 접근값을 사용하며, 별도 접근값이 필요한 환경에서는 `HDHOMERUN_FF_GROUP_APIKEY` 환경변수로 지정할 수 있습니다.

## 0.6.2 · NVIDIA 트랜스코딩 시험 기능

NVIDIA NVDEC·CUDA 전처리·NVENC H.264 출력을 선택 기능으로 추가했습니다. **홈런이 없는 상태에서 트랜스코딩만 확인했습니다.** 일본 사택의 RTX 2070 / FFmpeg 4.4.2 환경에서 검증했으며, 사용해 볼 분은 해당 서버에서 **NVIDIA 실제 변환 검사**를 먼저 실행하세요. 검사를 통과하면 출력 목록과 NVIDIA 전용 M3U가 표시됩니다. 기본 출력은 CPU 변환을 유지합니다.

## 목표 흐름

```text
HDHomeRun → HDHomeRun Live for Shyni → FFmpeg → Shyni용 M3U/HLS
```

TVHeadend는 이 플러그인의 재생 경로에 필요하지 않습니다. 기존 `tvh_m3u_plugin`과는 별도 DB·API·HLS 캐시를 사용하므로 함께 설치할 수 있습니다.

## 초기 사용 순서

1. HDHomeRun LAN 주소를 입력합니다.
2. 장비 정보를 확인합니다.
   장비 이름·모델·ID·펌웨어·총 튜너 수·최근 확인 시점과 각 튜너 상태가 표시됩니다. FF에서 사용할 최대 튜너 수는 전체 자동 또는 1~장비 최대값 중 선택해 저장·적용할 수 있습니다. 튜너는 동시 RF 수신 수이며, 아래 방송 채널 목록의 개수와는 별개입니다.
3. 필요하면 장비의 native lineup을 가져와 채널 목록을 검토합니다. 이 목록은 HDHomeRun의 현재 channel map 결과이며, CMB 프리셋과 무관합니다.
4. `자동`으로 채널 탐색을 시작합니다. 처음에는 한국 152개 주파수를 VSB/8·QAM 자동 판별로 각각 확인합니다(304개 조합). QAM은 64/256을 판별하고 실제 수신 변조를 저장합니다. 수신 결과가 저장된 다음부터는 발견한 조합만 빠르게 재탐색합니다. 필요하면 한국 전체 탐색이나 CMB 수동 프리셋도 선택할 수 있습니다.
5. 채널 목록에서 사용할 채널을 체크합니다. 이름이 수신된 채널은 기본 선택되며, 암호화·제어·데이터 없음 서비스는 M3U에서 제외됩니다.
6. 원본 주소 형식은 `자동 확인`으로 두고 `원본 주소 호환성 확인`을 실행합니다. 확장자 없음·`.mpeg`를 실제 영상 수신으로 확인하며, 장비·펌웨어·주소·설정별 결과를 기억합니다. 필요하면 형식을 수동 지정할 수 있습니다.
7. Shyni에는 `Shyni 기본 M3U` 또는 `H.264/AAC 변환 전용 M3U`를 등록합니다. 기본 출력은 H.264/AAC 트랜스코딩이며 FF가 재생할 때 실시간 변환합니다. `원본 전용 M3U`는 코덱 변환을 하지 않습니다. M3U 채널 출처의 기본값은 스캔 결과이며, native lineup은 별도 선택할 수 있습니다.

스캔은 유휴 튜너 하나만 사용하며, 주파수 tune·서비스 판독 결과는 각 FF의 로컬 DB에 저장합니다. 발견한 주파수는 JSON 프리셋으로 내려받을 수 있습니다. 0.2 버전에서 이미 스캔한 설치본도 저장된 결과로 빠른 재탐색을 시작할 수 있습니다.

지정한 튜너 수 N은 스캔·주소 호환성 확인·직접 주파수 재생·native lineup 재생 모두에 적용됩니다. FF는 장비의 앞 N개 튜너 범위에서만 유휴 튜너를 예약합니다. 줄이면 범위 밖의 FF 재생은 종료하고 활성 스캔에는 취소를 요청하며, 다른 클라이언트의 잠금을 강제로 해제하지 않습니다. 장비 / 채널 화면에는 발견 서비스 수·사용 가능한 일반 방송 수·사용 선택 수를 따로 표시합니다.

메뉴는 항목별로 분리됩니다. 장비 / 채널은 장비 연결·튜너 할당·채널 선택, 주파수 프리셋은 탐색·진행 상황, 재생 / API는 트랜스코딩·버퍼·M3U, 진단은 FFmpeg 지원 정보를 표시합니다.

스캔 채널의 HLS 재생은 유휴 튜너를 예약하고 해당 튜너만 `kr-bcast` 또는 `kr-cable`로 설정한 뒤 HTTP 원본을 FFmpeg로 받습니다. 같은 채널·출력 형식은 스트림 하나를 공유합니다. 인코더 종료나 유휴 종료 시 튜너를 해제하고 이전 채널맵을 복원합니다. 이미 다른 클라이언트가 사용 중이면 강제 잠금 해제하지 않습니다.

스캔은 프리셋의 VSB/8·QAM/256을 각각 `8vsb:<frequency>`·`qam256:<frequency>`로 직접 튜닝합니다. 장비의 `auto` 모드는 현재 channel map의 영향을 받으므로 사용하지 않습니다. 0.2.0에서 VSB 채널이나 이름이 누락됐다면 0.2.1로 갱신 후 프리셋 스캔을 다시 실행하세요. 채널명은 방송의 streaminfo에서 수신하며, 이름이 없는 서비스와 암호화·제어 서비스 상태를 구분해 표시합니다.

채널 목록의 **사용** 체크박스는 즉시 저장됩니다. 사용자가 변경한 선택은 같은 채널의 재스캔에서도 유지됩니다. 스캔 상태 조회는 FF 공통 로딩 표시 없이 실행하고 완료·취소·실패 시 멈춥니다.

## 재생 프로필

- `copy`: 원본 MPEG-TS 코덱을 보존합니다.
- `copy_video_aac`: 영상 코덱·해상도는 유지하고 음성만 AAC로 바꿉니다. MPEG-2 영상을 지원하는 TV에서 AC3 음성 호환성을 비교할 때 사용할 수 있습니다.
- `mobile_cpu` (기본 안정형): 최대 720p/29.97fps, H.264 약 3Mbps(최대 4Mbps) + AAC로 변환합니다. 작은 NAS의 처리 여유와 원격 시청 안정성을 확보하고 SD 영상은 확대하지 않습니다.
- `mobile_1080` (고화질): 원본 해상도를 유지해 H.264/AAC로 변환합니다. CPU·통신 처리량에 여유가 있는 경우 선택합니다.
- `mobile_vaapi`: 영상 디코딩·Bob 디인터레이스·크기 조절·H.264 인코딩은 VAAPI GPU 경로, 음성은 CPU의 AAC를 사용합니다. 실제 변환 검사를 통과한 장비에서만 저장·재생할 수 있습니다. 입력 영상 코덱도 GPU가 디코딩할 수 있어야 합니다.
- `mobile_nvenc` (시험 기능): NVIDIA NVDEC 디코딩 → CUDA 디인터레이스·크기 조절 → NVENC H.264 인코딩을 사용합니다. 음성은 CPU AAC입니다. 해당 서버의 실제 변환 검사를 통과한 경우에만 선택할 수 있습니다.

동일 채널·출력 형식은 변환 스트림 하나를 공유합니다. 기본 설정은 최신 영상 약 4초를 제외한 목록을 제공합니다. 플레이어에는 최소 3개 조각(약 6초)을 제공하므로 기본 첫 재생 준비 분량은 약 10초이며 원본 연결·플레이어의 대기는 추가될 수 있습니다. 최근 180초 분량의 재생 목록과 추가 삭제 유예를 두어 순환 저장하며 무기한 녹화하지 않습니다.

FF 화면에서 최대 해상도, 영상 목표/최대 비트레이트, FPS, CPU 스레드, 인코더 preset, 음성 비트레이트, 저장 지연/보관 창, 음성 싱크(ms)를 수정할 수 있습니다. 영상 크기·비트레이트·FPS는 `mobile_cpu`·`mobile_vaapi`·`mobile_nvenc`에 적용되며, 인코더 preset과 CPU 스레드는 CPU 모드 전용입니다. VAAPI·NVIDIA 경로의 디코더·필터 호스트 스레드는 2개로 고정하고 NVIDIA 인코더 preset은 `fast`를 사용합니다. 음성 싱크와 저장 버퍼는 원본 모드에도 적용됩니다. 음성이 늦으면 음수로 앞당기며 기본값은 0입니다. 원본 코덱을 유지한 음성 시각 보정은 FFmpeg `setts` 비트스트림 필터를 사용합니다.

트랜스코딩 / 저장 버퍼 설정에는 선택한 출력의 영상·음성 코덱과 인코더, VAAPI·NVIDIA 사용 여부가 표시됩니다. CPU H.264 변환은 `libx264`, VAAPI 영상 변환은 `h264_vaapi`, NVIDIA 영상 변환은 `h264_nvenc`, 음성 변환은 CPU의 `aac`를 사용합니다. 원본 유지(`copy`)는 채널별 원본 코덱을 유지하며 재인코딩하지 않습니다. 표시는 새 재생에 사용할 설정을 기준으로 하며, 출력 방식을 선택하면 함께 바뀝니다.

`변환 설정 저장`은 다음 새 스트림부터 적용됩니다. `저장·현재 재생에 적용`은 현재 FF 스트림을 종료하고 재생을 다시 시작할 때 반영하며, FF 전체를 재시작하지 않습니다. 출력 방식을 바꿀 때는 선택을 반영하는 `Shyni 기본 M3U`에서 채널 목록을 새로고침해야 합니다. 변환 전용/원본 전용 M3U는 출력 방식이 고정됩니다.

## VAAPI 하드웨어 인코딩

FF 컨테이너에 `/dev/dri`를 연결하고 `/dev/dri/renderD128`에 접근할 수 있어야 합니다. FFmpeg의 `h264_vaapi` 지원과 GPU에 맞는 사용자 공간 드라이버도 필요합니다. 인코더 목록에 이름이 있다는 것만으로 실제 인코딩이 가능하다는 뜻은 아닙니다.

재생 / API의 트랜스코딩 / 저장 버퍼 설정에서 드라이버를 선택하고 **VAAPI 실제 변환 검사**를 실행하세요. 자동은 시스템 설정, i965는 구형 인텔, iHD는 신형 인텔용 선택지입니다. 호환 여부는 실제 검사로 판단합니다. 검사는 튜너 없이 720p MPEG-2 인터레이스 테스트 영상 30프레임을 생성하고 GPU 디코딩·디인터레이스·크기 조절·H.264 인코딩까지 확인합니다. 결과는 잠시 캐시되며 FF 재시작이나 드라이버 변경 뒤에는 새 재생 전 다시 확인합니다. 검사 실패 시 방송 튜너를 확보하거나 GPU 스트림을 시작하지 않으며 CPU 모드를 직접 선택할 수 있습니다.

일부 구형 인텔 NAS에서는 시스템의 기본 i965 패키지로 인코딩이 실패하고 셰이더 포함 드라이버가 필요할 수 있습니다. 시놀로지 916의 N3710, Ubuntu 22.04 amd64 기반 FF 환경에서는 `i965-va-driver-shaders` 2.4.1-1을 별도 경로에서 사용해 검증했습니다. 해당 환경용 패키지 SHA-256은 `f36bb525528a5ec3aff22a46251799fe3a525338cb2553a586efa35bb96c70a8`입니다. 다른 운영체제·아키텍처에 이 바이너리를 그대로 사용하지 마세요.

호환 드라이버를 별도로 준비하는 경우 `i965_drv_video.so`와 해당 저작권 문서를 FF 데이터의 `hdhomerun_ff/vaapi/i965`에 보관하세요. 컨테이너에서는 `/data/hdhomerun_ff/vaapi/i965`로 보입니다. **i965 선택 시에만** 이 경로를 우선 사용하고, 다른 플러그인이나 FF의 전역 드라이버 설정은 변경하지 않습니다. 데이터 볼륨을 유지하면 컨테이너 재생성 후에도 드라이버 파일이 남습니다. 플러그인은 드라이버를 자동 다운로드하거나 시스템 패키지를 교체하지 않습니다.

검사 통과 후 VAAPI 출력을 저장하고 Shyni 기본 M3U의 채널 목록을 새로고침하거나 **VAAPI H.264/AAC 전용 M3U**를 등록하세요. 기존 H.264/AAC 변환 전용 주소는 계속 CPU 모드를 사용합니다. 저장·현재 재생에 적용은 FF의 현재 스트림을 종료하므로 Shyni에서 다시 재생해야 합니다.

## NVIDIA 하드웨어 변환 · 시험 기능

호스트의 NVIDIA 드라이버와 NVIDIA Container Toolkit, FF 컨테이너의 GPU 연결이 필요합니다. 컨테이너에 `compute,video,utility` 드라이버 기능을 전달하고, FFmpeg가 CUDA 하드웨어 디코딩·`yadif_cuda`·`scale_cuda`·`h264_nvenc`를 지원해야 합니다. 플러그인이 호스트 드라이버나 컨테이너 구성을 변경하지는 않습니다.

재생 / API에서 **NVIDIA 실제 변환 검사**를 실행하면 튜너 없이 1080i MPEG-2 샘플을 생성해 720p H.264로 변환합니다. 인코더 이름의 존재가 아니라 실제 디코딩·전처리·인코딩 성공 여부를 판단합니다. 검사를 통과한 서버에만 NVIDIA 출력 선택지와 전용 M3U 주소를 표시하며, 저장과 새 스트림 시작 시에도 사용 가능 여부를 검사합니다. 성공 결과는 5분, 실패 결과는 30초 캐시하며 FF 재시작 후에는 다시 검사해야 합니다. 저장된 NVIDIA 출력이 미검사 상태이면 재검사가 필요한 선택지로 표시합니다.

사용하려면 검사 통과 후 `NVIDIA` 출력을 직접 선택해 저장하고 Shyni 기본 M3U를 새로고침하거나 **NVIDIA H.264/AAC 전용 M3U**를 등록하세요. 기존 CPU 전용 주소는 계속 CPU를 사용합니다. 실패하면 CPU 출력을 선택해 저장할 수 있습니다. 실제 방송의 입력 코덱·해상도와 동시 변환 수에 따른 사용 가능 여부는 각 GPU 환경에서 확인하세요.

## 보안 원칙

- Shyni M3U에는 HDHomeRun의 LAN 원본 주소가 노출되지 않습니다.
- 장비 검색/가져오기 API는 플러그인 관리자 메뉴에서만 사용합니다.
- 외부 재생은 FF의 API 키가 포함된 HLS 프록시 주소만 사용합니다.
