# HDHomeRun Live for Shyni

FF(FlaskFarm)에서 HDHomeRun 채널을 직접 읽고, Shyni 라이브 TV에 넣을 M3U/HLS 주소를 제공하는 플러그인입니다.

## 목표 흐름

```text
HDHomeRun → HDHomeRun Live for Shyni → FFmpeg → Shyni용 M3U/HLS
```

TVHeadend는 이 플러그인의 재생 경로에 필요하지 않습니다. 기존 `tvh_m3u_plugin`과는 별도 DB·API·HLS 캐시를 사용하므로 함께 설치할 수 있습니다.

## 초기 사용 순서

1. HDHomeRun LAN 주소를 입력합니다.
2. 장비 정보를 확인합니다.
   장비 이름·모델·ID·펌웨어·총 튜너 수·최근 확인 시점과 각 튜너 상태가 표시됩니다. FF에서 사용할 최대 튜너 수는 전체 자동 또는 1~장비 최대값 중 선택해 저장·적용할 수 있습니다. 튜너는 동시 RF 수신 수이며, 아래 방송 채널 목록의 개수와는 별개입니다.
3. 필요하면 장비의 native lineup을 가져와 채널 목록을 검토합니다. 이 목록은 HDHomeRun의 현재 channel map 결과이며, CMB 프리셋과 무관합니다.
4. `자동`으로 채널 탐색을 시작합니다. 처음에는 한국 152개 주파수를 VSB/8·QAM 자동 판별로 각각 확인합니다(304개 조합). QAM은 64/256을 판별하고 실제 수신 변조를 저장합니다. 수신 결과가 저장된 다음부터는 발견한 조합만 빠르게 재탐색합니다. 필요하면 한국 전체 탐색이나 CMB 수동 프리셋도 선택할 수 있습니다.
5. 채널 목록에서 사용할 채널을 체크합니다. 이름이 수신된 채널은 기본 선택되며, 암호화·제어·데이터 없음 서비스는 M3U에서 제외됩니다.
6. 원본 주소 형식은 `자동 확인`으로 두고 `원본 주소 호환성 확인`을 실행합니다. 확장자 없음·`.mpeg`를 실제 영상 수신으로 확인하며, 장비·펌웨어·주소·설정별 결과를 기억합니다. 필요하면 형식을 수동 지정할 수 있습니다.
7. Shyni에는 `Shyni 기본 M3U` 또는 `H.264/AAC 변환 전용 M3U`를 등록합니다. 기본 출력은 H.264/AAC 트랜스코딩이며 FF가 재생할 때 실시간 변환합니다. `원본 전용 M3U`는 코덱 변환을 하지 않습니다. M3U 채널 출처의 기본값은 스캔 결과이며, native lineup은 별도 선택할 수 있습니다.

스캔은 유휴 튜너 하나만 사용하며, 주파수 tune·서비스 판독 결과는 각 FF의 로컬 DB에 저장합니다. 발견한 주파수는 JSON 프리셋으로 내려받을 수 있습니다. 0.2 버전에서 이미 스캔한 설치본도 저장된 결과로 빠른 재탐색을 시작할 수 있습니다.

지정한 튜너 수 N은 스캔·주소 호환성 확인·직접 주파수 재생·native lineup 재생 모두에 적용됩니다. FF는 장비의 앞 N개 튜너 범위에서만 유휴 튜너를 예약합니다. 줄이면 범위 밖의 FF 재생은 종료하고 활성 스캔에는 취소를 요청하며, 다른 클라이언트의 잠금을 강제로 해제하지 않습니다. 장비 / 채널 화면에는 발견 서비스 수·사용 가능한 일반 방송 수·사용 선택 수를 따로 표시합니다.

메뉴는 항목별로 분리됩니다. 장비 / 채널은 장비 연결·튜너 할당·채널 선택, 주파수 프리셋은 탐색·진행 상황, 재생 / API는 트랜스코딩·버퍼·M3U, 진단은 FFmpeg 지원 정보를 표시합니다.

스캔 채널의 HLS 재생은 유휴 튜너를 예약하고 해당 튜너만 `kr-bcast` 또는 `kr-cable`로 설정한 뒤 HTTP 원본을 FFmpeg로 받습니다. 같은 채널·출력 형식은 스트림 하나를 공유합니다. 인코더 종료나 유휴 종료 시 튜너를 해제하고 이전 채널맵을 복원합니다. 이미 다른 클라이언트가 사용 중이면 강제 잠금 해제하지 않습니다.

스캔은 프리셋의 VSB/8·QAM/256을 각각 `8vsb:<frequency>`·`qam256:<frequency>`로 직접 튜닝합니다. 장비의 `auto` 모드는 현재 channel map의 영향을 받으므로 사용하지 않습니다. 0.2.0에서 VSB 채널이나 이름이 누락됐다면 0.2.1로 갱신 후 프리셋 스캔을 다시 실행하세요. 채널명은 방송의 streaminfo에서 수신하며, 이름이 없는 서비스와 암호화·제어 서비스 상태를 구분해 표시합니다.

채널 목록의 **사용** 체크박스는 즉시 저장됩니다. 사용자가 변경한 선택은 같은 채널의 재스캔에서도 유지됩니다. 스캔 상태 조회는 FF 공통 로딩 표시 없이 실행하고 완료·취소·실패 시 멈춥니다.

## 재생 프로필

- `copy`: 원본 MPEG-TS 코덱을 보존합니다.
- `copy_video_aac`: 영상 코덱·해상도는 유지하고 음성만 AAC로 바꿉니다. MPEG-2 영상을 지원하는 TV에서 AC3 음성 호환성을 비교할 때 사용할 수 있습니다.
- `mobile_cpu` (기본 안정형): 최대 720p/29.97fps, H.264 약 3Mbps(최대 4Mbps) + AAC로 변환합니다. 작은 NAS의 처리 여유와 원격 시청 안정성을 확보하고 SD 영상은 확대하지 않습니다.
- `mobile_1080` (고화질): 원본 해상도를 유지해 H.264/AAC로 변환합니다. CPU·통신 처리량에 여유가 있는 경우 선택합니다.

동일 채널·출력 형식은 변환 스트림 하나를 공유합니다. 기본 설정은 영상을 12초 먼저 저장하고 최신 12초 조각을 제외한 목록을 제공합니다. 플레이어에는 최소 3개 조각(약 6초)을 제공하므로 첫 재생 준비에는 약 18초와 원본 연결 시간이 필요합니다. 최근 180초 분량의 재생 목록과 추가 삭제 유예를 두어 순환 저장하며 무기한 녹화하지 않습니다.

FF 화면에서 최대 해상도, 영상 목표/최대 비트레이트, FPS, CPU 스레드, 인코더 preset, 음성 비트레이트, 저장 지연/보관 창, 음성 싱크(ms)를 수정할 수 있습니다. 영상 세부 설정은 `mobile_cpu`에 적용되며, 음성 싱크와 저장 버퍼는 원본 모드에도 적용됩니다. 음성이 늦으면 음수로 앞당기며 기본값은 0입니다. 원본 코덱을 유지한 음성 시각 보정은 FFmpeg `setts` 비트스트림 필터를 사용합니다.

`변환 설정 저장`은 다음 새 스트림부터 적용됩니다. `저장·현재 재생에 적용`은 현재 FF 스트림을 종료하고 재생을 다시 시작할 때 반영하며, FF 전체를 재시작하지 않습니다. 출력 방식을 바꿀 때는 선택을 반영하는 `Shyni 기본 M3U`에서 채널 목록을 새로고침해야 합니다. 변환 전용/원본 전용 M3U는 출력 방식이 고정됩니다.

VAAPI는 단순히 FFmpeg 목록에 보인다고 활성화하지 않습니다. 실제 인코딩 진단이 통과한 환경에서만 별도 프로필로 추가해야 합니다.

## 보안 원칙

- Shyni M3U에는 HDHomeRun의 LAN 원본 주소가 노출되지 않습니다.
- 장비 검색/가져오기 API는 플러그인 관리자 메뉴에서만 사용합니다.
- 외부 재생은 FF의 API 키가 포함된 HLS 프록시 주소만 사용합니다.
